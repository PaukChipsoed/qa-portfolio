# API Testing — Личные события

## Инструмент

Для тестирования API использовался **Postman**.

## Что проверял

- HTTP-методы;
- статус-коды ответов;
- структуру JSON;
- обязательные параметры;
- корректность передаваемых данных;
- позитивные сценарии;
- негативные сценарии;
- обработку ошибок API;
- создание личного события;
- редактирование личного события;
- удаление личного события.

## Тестовая коллекция

Для тестирования была создана коллекция Postman с разделением сценариев на позитивные и негативные проверки.

Всего подготовлено **15 API-тестов**:

- 10 позитивных;
- 5 негативных.

## Переменные

В запросах использовались переменные:

- `{{baseUrl}}` — базовый URL API;
- `{{myToken}}` — токен авторизации.

Для связанных сценариев сохранялся `eventId` созданного события и использовался в последующих запросах.

## Автоматизация проверок в Postman

В запросах использовались тестовые скрипты для проверки:

- HTTP status code;
- наличия данных в ответе;
- сохранения идентификатора созданного события.

Пример логики:

1. Создать личное событие.
2. Проверить успешный статус ответа.
3. Получить `eventId`.
4. Сохранить `eventId`.
5. Использовать его для дальнейшего редактирования или удаления события.

## Проверяемые сценарии

### Позитивные

- создание личного события с корректными данными;
- получение данных события;
- редактирование события;
- удаление события;
- работа с корректными параметрами запроса.

### Негативные

- отсутствие обязательных параметров;
- некорректные значения параметров;
- использование некорректных данных;
- проверка ошибок авторизации;
- проверка обработки ошибочных запросов.

## Результат

API было проверено с использованием позитивных и негативных сценариев. Для повторного выполнения тестов использовались переменные Postman и тестовые скрипты.
